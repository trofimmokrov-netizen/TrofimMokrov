Как согласовывать статьи и цены сайта через GitHub Pull Request

Редакционный процесс для сайта в GitHub. Один смысл правки, проверка разницы, подтверждение цены и история принятого решения.

В этой статье
  1. Запишите, чьё решение меняет сайт
  2. Соберите изменения одной темы
  3. Сверьте исходный текст и итог страницы
  4. Сохраните причину и результат правки

Запишите, чьё решение меняет сайт

Для правки цены заведите рабочую запись с новой формулировкой, основанием и сотрудником, подтверждающим условия. Для статьи укажите вопрос читателя и исходные материалы. Отметьте, какие страницы или файлы должны измениться. Это позволит редактору понять замысел без поиска по переписке. Например, если изменилась стоимость установки, проверьте, встречается ли она в каталоге, статье и мини-приложении. Уточните, какие упоминания относятся к действующим условиям, а какие описывают прошлые события.

Соберите изменения одной темы

Создайте рабочую ветку и откройте запрос на слияние, когда подготовлен хотя бы первый вариант. Для ещё незаконченного текста отметьте запрос как черновик. Связанные правки удобно держать вместе, чтобы код и содержание вступили в силу одновременно. Разные решения, например новую цену и замену иллюстраций портфолио, проще согласовать отдельно. Укажите, где редактор увидит нужную фразу, и добавьте ссылку на точную версию просмотра, если она собирается автоматически.

Сверьте исходный текст и итог страницы

Откройте список файлов и прочитайте смысловые изменения. Если сайт собирается из данных, найдите основной источник строки и проверьте, что сгенерированные страницы согласованы с ним. Проверка сборки может пройти успешно даже при опечатке в сумме. Для примера попросите редактора сверить четыре вещи. Это новая сумма, единица измерения, оговорка о составе работ и все запланированные места отображения. Если после согласования в запрос добавился новый коммит, повторно откройте изменившиеся строки перед слиянием.

Сохраните причину и результат правки

В обсуждении кратко зафиксируйте, какой вариант утверждён и где выполнена проверка. После слияния убедитесь, что основной канал публикации получил нужную версию. Если на сайте осталась старая цена, сравните опубликованную версию с принятой записью перед новой правкой. Пробный цикл полезно пройти с одним текстом и тремя местами отображения. Редактору должно быть понятно, кто утвердил содержание, какие страницы проверены и где найти последнее решение для следующего обновления.
