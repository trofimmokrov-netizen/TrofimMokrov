# Поиск клиентов — отдельный локальный инструмент

Прототип для поиска компаний и подготовки предложений о создании сайта. Не часть публичного сайта и не облачная CRM. Работает на Python 3.10+ без сторонних библиотек. Интерфейс в браузере, данные — SQLite на вашем компьютере.

## Что уже работает

- Поиск мебели и мастерских на открытой карте OpenStreetMap через Overpass — без API-ключа (нужен доступ к сервису). Дополнительно поддержаны салоны, автосервисы и стоматологии; прочие запросы ищутся по названию.
- Ограниченный парсер публичного сайта: robots.txt, главная и до двух страниц контактов, опубликованные email с указанием источника.
- Ручное добавление и импорт CSV (до 500 строк / 1 МБ за импорт).
- Сохранение компаний, дедупликация, поиск и фильтры.
- Раздельные статусы: сайт не указан / указан, но не проверен / доступен / результат неясен. Пустая карточка не считается доказательством отсутствия сайта.
- Проверка доступности указанного публичного сайта. Локальные адреса, нестандартные порты и редиректы на внутренние адреса не допускаются; HTTP-ошибка не переводит компанию в «без сайта».
- Ручное подтверждение отсутствия сайта после собственного исследования.
- Редактируемое предложение с названием компании, городом и ценой сайта от 10 000 ₽. Это шаблон с подстановкой данных, не подключённая языковая модель. Конкретную идею добавляет оператор.
- Одобрение письма перед отправкой; редактирование снимает одобрение.
- Отправка через SMTP с SSL/STARTTLS после явной команды. Можно отправить ограниченную очередь одобренных писем из CLI с интервалом.
- Защита от повторной отправки на один email, список «Не писать», журнал исходов.

## Запуск

Из корня репозитория:

```sh
python3 leadfinder/server.py
```

На Windows обычно используется `python` вместо `python3`. Откройте локальный адрес, который выведет команда. GitHub Pages не запускает Python: загрузка исходников в GitHub не создаёт работающий почтовый сервис. Секреты, база компаний и настройки почты на Pages не публикуются.

По умолчанию база хранится в `leadfinder/data/leads.sqlite3` (папка исключена из Git), сервер доступен только с этого компьютера. Резервную копию базы делайте при остановленном приложении. Другую базу можно указать через `--db /private/path/leads.sqlite3` или LEADFINDER_DB_PATH. Не запускайте два экземпляра или несколько отправщиков с одной базой одновременно.

Интерфейс не загружает сторонние скрипты, не предоставляет CORS-доступ и отклоняет POST без локального токена. Не меняйте bind на публичный адрес без отдельной настройки аутентификации, TLS, доступа и хранения данных.

## Первый рабочий сценарий без ключей

1. Подготовьте список компаний из источника, который можно использовать для этой цели.
2. Импортируйте CSV или добавьте запись вручную.
3. Откройте карточку компании и её источник. Проверьте фактическое отсутствие сайта — также поиском по названию и адресу. Отсутствие ссылки на картах недостаточно.
4. Если email пришёл из открытой карты, проверьте его назначение. Если у компании указан сайт — можно нажать «Разобрать сайт и найти email». Выберите найденный адрес с источником и сохраните. Если сайта и опубликованного email нет, инструмент не угадывает контакт и не отправляет формы на чужих сайтах.
5. Подтвердите результат проверки, подготовьте черновик, уточните предложение и сохраните.
6. Одобрите текст. После подключения почты можно отправить его отдельной кнопкой.
7. При просьбе больше не писать добавьте адрес в «Не писать» — последующие отправки и импорты учитывают список.

Пример формата (вымышленные данные, не получатели для реальной отправки):

```csv
name,city,address,category,website,email,source_url
Демо-мастерская,Москва,Пример адреса,Мебель,,owner@example.com,https://example.com
```

Поддерживаются запятая, точка с запятой и табуляция, UTF-8 с BOM или без. Обязателен только name. Повторный импорт не перезаписывает отредактированные сведения. Базовый ключ дедупликации: название + адрес + город; для Яндекса — ID организации. Разные источники иногда дают разные записи; отправка дополнительно ограничена по email.

## Поиск через Яндекс

Подготовлен адаптер **API Поиска по организациям** (`search-maps.yandex.ru/v1/`). Нужен именно доступ к этому API, не любой ключ JavaScript-карт. Официальная документация:
https://yandex.ru/maps-api/docs/businesssearchapi/index.html

Укажите YANDEX_SEARCH_API_KEY в защищённых настройках среды выполнения. В чат или репозиторий ключ не вставляйте. Нужен HTTPS-доступ к search-maps.yandex.ru. Проверьте подходящий тариф, текущий формат API и допустимость использования, хранения и экспорта данных перед подключением реальной базы. Скрейпинг интерфейса Яндекс Карт и обход ограничений не реализованы.

API возвращает кандидатов по сфере и региону, а не гарантированный полный список всех компаний. Географию и данные проверяйте по адресу организации. Поле «город» сохраняет контекст вашего поискового запроса. Для других стран можно задать иной регион, но фактический охват определяется провайдером. Для глобального поиска можно импортировать CSV от другого подходящего источника.

Яндекс не считается источником готовых email: если email не получен и не проверен, он остаётся пустым. Не обещается, что API предоставляет его в карточке.

**Статус проверки:** в текущей облачной среде ключ отсутствует, доступ к документации блокируется прокси (403). Формат адаптера проверен на тестовом ответе, живой поиск не выполнялся. Это незавершённое внешнее подключение, а не проверенная интеграция с реальным аккаунтом.

## Подключение почты

Приложение читает только переменные окружения процесса:

- SMTP_HOST — сервер вашего провайдера.
- SMTP_PORT — 465 для SSL или 587 для STARTTLS (проверка TLS включена).
- SMTP_USER — логин.
- SMTP_PASSWORD — пароль приложения или иной пароль SMTP, поддерживаемый провайдером.
- SMTP_FROM — один email отправителя, разрешённый у провайдера.

`.env.example` содержит только имена. Автоматическая загрузка `.env` не реализована; используйте защищённую конфигурацию процесса или менеджер секретов. Изменив окружение, перезапустите сервер.

Нужны действующие учётные данные и исходящий TCP-доступ к SMTP-провайдеру. HTTP-прокси не заменяет SMTP-соединение; proxy-placeholder вместо настоящего пароля может не работать в raw SMTP. В текущем облаке SMTP не настроен и реальные письма не отправлялись. Развёртывание на компьютере/сервере с доступом к почте — отдельный шаг.

Перед использованием своего домена настройте отправителя у почтового провайдера (SPF/DKIM/DMARC по его инструкции). Соблюдайте его ограничения на исходящие письма. Получатель должен понимать, кто пишет и как отказаться от дальнейших обращений. Приложение не читает ответы и отказы автоматически: их обрабатывает оператор и добавляет в «Не писать».

## Очередь одобренных писем

Без флага отправки команда только показывает количество и не отправляет письма:

```sh
python3 leadfinder/worker.py --limit 10
```

Для реальной отправки заранее одобренной очереди, после настройки SMTP:

```sh
python3 leadfinder/worker.py --send-approved --limit 10 --interval 30
```

Новые и не одобренные записи не отправляются. Максимальная пачка — 50, минимальный интервал — 5 секунд. По умолчанию 10 и 30 секунд. Работает один отправщик; не запускайте CLI одновременно с ручной отправкой в другом процессе. Планировщик ОС можно подключить позже, сохранив правило ручного одобрения записей.

`sent` означает принятие SMTP-сервером, не доставку и не прочтение. При неоднозначной ошибке — `unknown`: повторная отправка заблокирована, нужно проверить журналы провайдера. При прерывании процесса статус `sending` также не отправляется повторно автоматически; сначала проверьте почту и разберите запись. Автоматического сброса таких статусов нет. Отказ сервера (`failed`) можно исправить и снова одобрить, если известно, что письмо не принято.

## Проверки

```sh
python3 -m unittest discover -s leadfinder/tests -v
```

Проверяются импорт, повторные записи, одобрение, его отзыв при правке, блокировка адреса, неопределённая отправка, реакция на отказ SMTP, запрет внутренних URL, тестовый ответ Яндекса, HTTP-защита и пакетная очередь. Все сетевые операции провайдеров в тестах заменены тестовыми обработчиками. Тесты не отправляют реальных писем и не доказывают доступ к Яндексу или SMTP.

Браузерный сценарий проверен отдельно: CSV → карточка → подтверждение → черновик → одобрение → изменение → блокировка. Интерфейс проверен на 320, 390, 768 и 1440 px; без SMTP кнопка реальной отправки недоступна.

## Открытый поиск и парсеры

По умолчанию выбран запрос «Мебель и мастерские» и небольшой прямоугольник Москвы (55.49,37.32,55.96,37.95). OpenStreetMap — отдельный источник, не данные Яндекс Карт. Ключ не нужен, но нужны сеть и доступный публичный Overpass. Полнота и актуальность данных не гарантируются. Данные атрибутированы © OpenStreetMap contributors, лицензия ODbL: https://www.openstreetmap.org/copyright . Подробности публичных серверов: https://wiki.openstreetmap.org/wiki/Overpass_API .

В открытом поиске **географию задаёт поле координат**, а не название города. Для другой территории укажите её координаты; лимит области — 1° широты × 2° долготы, до 50 результатов. Для мебели запрос включает shop=furniture и craft=carpenter. Email и сайт берутся из тегов карточек, если они есть. Значения без сайта — кандидаты для дальнейшей проверки, не доказательство отсутствия сайта.

Парсер сайта работает только с известным публичным HTTP(S)-адресом компании, без авторизации. Он сначала читает robots.txt, соблюдает запрет и допустимый crawl-delay, читает максимум три HTML-страницы с интервалом не менее секунды. В скриптах контакты не ищет, чужие домены по ссылкам не обходит, CAPTCHA и запреты доступа не обходит. Сохраняются email, URL источника и тип находки (mailto / видимый текст). Если robots.txt не удаётся проверить, разбор останавливается. Результат не записывает найденный email вместо вашего автоматически и не одобряет письмо.

Если у компании нет сайта, парсеру нечего читать: остаются опубликованные контакты в карточке или иной проверенный источник. Автоматический вывод «сайта точно нет» и извлечение скрытых email не реализованы. Полноценная проверка по нескольким поисковым системам потребует отдельного источника поиска.

В текущей облачной среде запрос Overpass отклонён прокси (403), поэтому реальных компаний этим адаптером ещё не получено. Контракт поиска и парсер проверены на тестовых данных. В черновике настроек добавлен overpass-api.de; изменения надо сохранить в настройках и опубликовать среду. Для разбора сайтов компаний также нужен разрешённый HTTPS-доступ к конкретным выбранным доменам: общий обход сетевой политики не применяется. На обычном компьютере ограничения доступа зависят от его сети.

Если пользуетесь только открытым поиском, ключ Яндекса не нужен; ранее добавленное требование YANDEX_SEARCH_API_KEY можно убрать в настройках среды. Поиск Яндекса остаётся отдельным вариантом.
