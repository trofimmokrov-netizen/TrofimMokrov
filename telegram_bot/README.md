# TrofimAI — меню и заявки в Telegram

Сайт открывает `@TrofimAI_bot` с параметром `start`. Из карточки услуги передаётся её идентификатор; из общих кнопок — `site`. Личная ссылка `@TrofimMokrov` сохранена отдельно.

Бот — отдельный Python 3.10+ процесс без сторонних библиотек. Он получает обновления через long polling, показывает услуги и цены из `content/services.json`, портфолио и контакты, собирает описание задачи и контакт, показывает итог перед отправкой. Только кнопка «Отправить заявку» создаёт запись в SQLite и уведомление владельцу. Молчание и отмена заявку не создают. Пользователь получает номер сохранённой заявки, а не обещание её прочтения.

## Настройки

Значения задаются в защищённых настройках среды или менеджере секретов сервера. Не вставляйте токен в исходники, HTML, команды чата или коммитируемые файлы.

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен `@TrofimAI_bot`, выданный BotFather. Используется выбранный владельцем текущий токен; значение хранится только в защищённых настройках процесса. |
| `TELEGRAM_OWNER_CHAT_ID` | Числовой ID личного чата владельца или выбранной группы для уведомлений. Владелец должен сначала написать боту; в группе бот должен иметь право отправлять сообщения. |
| `TROFIM_BOT_DB` | Постоянная база вне публичного каталога сайта. Для этой облачной среды: `/workspace/.trofimai/requests.sqlite3`. По умолчанию: `~/.local/share/trofimai/requests.sqlite3`. |
| `TELEGRAM_MINIAPP_URL` | Опубликованный HTTPS-адрес `https://trofimmokrov-netizen.github.io/TrofimMokrov/miniapp/`. Включает кнопку «Открыть приложение» на клавиатуре. |

Нужен разрешённый HTTPS-доступ к `api.telegram.org` через настроенный прокси с проверкой TLS. Токен приложения не заменяет настройку сетевого доступа. База содержит контакты и тексты заявок: не размещайте её в GitHub, на статическом хостинге или в общедоступной папке. Новая база создаётся с правами `0600`.

## Проверка и запуск

Из `/workspace/TrofimMokrov`:

```sh
python3 -m unittest discover -s telegram_bot/tests -v
python3 -m telegram_bot.run --check --db /workspace/.trofimai/requests.sqlite3
python3 -m telegram_bot.run --db /workspace/.trofimai/requests.sqlite3
```

`--check` вызывает только `getMe` и `getWebhookInfo`: проверяет принадлежность токена нужному боту и отсутствие webhook. Он не читает сообщения, не меняет команды и не отправляет уведомления. Код выхода `0` — эти проверки успешны и задан получатель; `2` — получатель не задан; `1` — ошибка настройки или доступа. Наличие chat ID ещё не подтверждает, что Telegram разрешит уведомление этому получателю.

Если ID владельца неизвестен, запустите процесс сначала без `TELEGRAM_OWNER_CHAT_ID`, откройте `@TrofimAI_bot` и отправьте `/id`. Бот покажет ID текущего личного чата. Сохраните его в настройках `TELEGRAM_OWNER_CHAT_ID` и перезапустите процесс. До этого приём заявок отключён, а меню, контакты и `/id` доступны. Не выбирайте получателя автоматически по первому посетителю бота.

При старте рабочий процесс регистрирует команды `/start`, `/services`, `/about`, `/site`, `/portfolio`, `/help`, `/request`, `/menu`, `/cancel` и `/id`. Если уже установлен webhook, процесс останавливается и не удаляет его. Сначала выясните, какой сервис сейчас обслуживает бота. Запускайте только один обработчик одного токена. Блокировка базы защищает от второго процесса с той же базой, но не обнаруживает другой сервер; Telegram сообщает о конфликте при получении обновлений.

Для работы постоянно нужен сервер или служба с автоматическим перезапуском, постоянным диском и этими переменными. Процесс, запущенный внутри задачи Codex, не является постоянным размещением. GitHub Pages запускает только сайт. Одна публикация статических файлов на Vercel этот процесс не запустит; для Vercel Functions потребуется отдельная реализация webhook и внешнее постоянное хранилище.

## Проверка заявки после настройки

1. Откройте на сайте кнопку заявки у конкретной услуги: Telegram должен передать выбранную услугу после нажатия «Запустить».
2. Введите описание и контакт, проверьте итог. До подтверждения записи в таблице заявок нет.
3. Нажмите «Отправить заявку»: бот должен вернуть номер, а владелец — получить услугу, описание, контакт и источник.
4. Убедитесь, что номер и данные совпадают. Отмена следующего черновика не должна создавать заявку.
5. Перезапустите процесс: сохранённая заявка должна остаться, повторного уведомления быть не должно.

Этот живой сценарий требует действующего защищённого токена, запущенного процесса и доступного чата владельца. Локальные тесты используют подмену Telegram API и не подтверждают реальную доставку.

## Надёжность и диагностика

Если `/start` не отвечает, сначала проверьте, запущен ли процесс и читает ли он обновления. Текст команды обрабатывается только работающим процессом; опубликованная страница Mini App его не заменяет. В текущей облачной среде используется отдельный фоновый процесс с журналом `/workspace/.trofimai/worker.log` и PID-файлом `/workspace/.trofimai/worker.pid`. Не доверяйте одному PID-файлу: проверяйте существование нужного процесса и его блокировку базы.

Для обычного сервера после защищённой настройки переменных можно запускать процесс через менеджер служб. Временный фоновый запуск из корня репозитория:

```sh
umask 077
mkdir -p /workspace/.trofimai
nohup python3 -u -m telegram_bot.run --db /workspace/.trofimai/requests.sqlite3 >> /workspace/.trofimai/worker.log 2>&1 < /dev/null &
```

Блокировка базы не позволяет двум обработчикам использовать её одновременно. Фоновый запуск не переживает остановку всей облачной машины и не заменяет постоянный хостинг. При временном явном отказе Telegram `5xx` чтение обновлений повторяется; `401` и конфликт обработчиков `409` требуют диагностики.

## Описание в Telegram

Тексты раздела «О боте» и экрана перед запуском находятся в `telegram_bot/profile.py`. Для явного обновления, когда секрет уже доступен в окружении:

```sh
python3 -m telegram_bot.profile
```

Команда проверяет @username, сохраняет короткое и полное описания для языка по умолчанию и русского, затем считывает их обратно. Она не меняет имя бота, токен и webhook и не выполняется автоматически при обычном перезапуске.

## Состояния доставки

Заявка, состояние диалога, отметка обновления и исходящая очередь фиксируются транзакцией. Повторно доставленный `update_id` не создаёт дубликат. Черновики удаляются после суток; не более трёх подтверждённых заявок от одного клиентского чата за 24 часа; для проверки владельцем — до десяти. Диалоги принимаются только в личных чатах. При передаче контакта кнопкой бот проверяет, что это контакт отправителя.

Уведомления имеют статусы `pending`, `sent`, `failed` и `unknown`. `sent` означает успешный ответ Telegram, а не прочтение. Явный отказ `429` откладывает отправки; явные `5xx` повторяются ограниченное число раз. Сетевой обрыв во время отправки или остановка процесса с записью `sending` переводит её в `unknown`; автоматического повтора нет, поскольку сообщение могло уже дойти. Неопределённый исход нужно проверить в Telegram до ручного повторения. Заявка остаётся в базе при любой ошибке доставки.

Агрегированные счётчики без контактов и текстов:

```sh
python3 -m telegram_bot.run --status --db /workspace/.trofimai/requests.sqlite3
```

Локальная команда использует ту же блокировку базы: сначала остановите процесс. Владелец также может запросить `/status` у работающего бота. `failed`/`unknown` требуют проверки уведомлений и базы владельцем; автоматической панели повторной отправки нет. Резервную копию базы делайте при остановленном процессе. Срок хранения подтверждённых заявок и их удаление определяет владелец; автоматического удаления этих записей нет.

При изменении цен и контактов перезапускайте процесс: содержимое JSON считывается на старте. Notion, Gmail и CRM этим модулем пока не подключены.

## Пробные задачи

Команда `/pilot` и кнопка «Пробная задача» открывают отдельный формат запроса. После контакта бот отдельно спрашивает, хочет ли клиент обсудить кейс для портфолио; затем показывает заявку для подтверждения. Выбор сохраняется в заявке и уведомлении владельцу. Публикация работы требует последующего отдельного согласования. Старые заявки и активные обычные диалоги сохраняются при обновлении. Описание предложения — `content/pilot.json`; руководство — [docs/PILOT.md](../docs/PILOT.md).
